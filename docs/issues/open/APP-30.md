#### APP-30 A file made in one app opens in the other
- Status: todo
- Priority: medium
- Needs: APP-16, APP-26
- Modified: 2026-11-16
- Do: Owner request, 2026-11-16: anything a person makes in the frontend can be exported as JSON and imported into the human CLI, and the other way round. One envelope for every file: `{"riftweave": "<kind>", "rules_version", "modules", "data"}` (`modules`: the enabled module ids and versions, APP-25) with kind `character` (a stored actor, `stored_actor.json`), `spell` (APP-10's author export), `session` (APP-16's `.riftweave.json`), and `settings` (APP-25) [A]; `data` is exactly what the command contract already returns, so no format is new. A character file also carries its sync fields (APP-33). The frontend gets "Export" on each screen that makes one and one "Import" on the home page that reads the kind; the CLI gets `riftweave export <kind> ...` / `riftweave import <file>` and an Import entry in the main menu. A file whose `rules_version` differs warns and still opens when the contract validates it [A]; a file that does not validate is refused with the schema's messages. A file whose `modules` differ from this device's is checked before it applies: a module item this device does not load would be lost, so the import (and any later update written over that file) stops with an alert naming the module and the rows at stake, and goes on only if the person enables the module or confirms the loss (owner, 2026-11-16).
