#### FE_S12_04_frontend-observability The frontend is observable, and exports its diagnostics
- Status: todo
- Priority: low
- Needs: APP-43
- Was: APP-46
- Modified: 2026-11-18
- Do: Owner request, 2026-11-18: the Angular app records what APP-43 defines, offline first.
  - **What:** an Angular `ErrorHandler` that records each uncaught error as a log record; a span for each API call (the command, the transport, WASM or HTTP, the duration, the outcome) and for the WASM core's start-up; route changes as spans [A].
  - **How:** a `Telemetry` service (signals first, per the conventions) that keeps the records in a capped buffer in IndexedDB when the setting is `local`, and posts OTLP/JSON to the endpoint when it is `export`. Decide in the spec step between `@opentelemetry/sdk-trace-web` and a small OTLP/JSON writer of our own, by bundle size against the Pages build [A].
  - **Trace context:** `httpTransport` sends `traceparent`, so a call and the server's span are one trace (APP-44).
  - **Diagnostics:** Settings gains "Export diagnostics", a file of the buffered records in OTLP/JSON, and "Clear diagnostics".
- Keys: the `Telemetry` service
- Files: ~10 (frontend/src/app/telemetry.ts, frontend/src/app/api.ts, frontend/src/app/wasm.ts, frontend/src/main.ts, frontend/src/app/settings-screens.ts, settings-screens.html, frontend/src/app/app.spec.ts, frontend/e2e/menus.spec.ts, docs/backend/frontend.md, docs/backend/observability.md)
