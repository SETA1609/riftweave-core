#### M5-70 First normal form: one kind of value per field
- Status: review
- Priority: high
- Needs: —
- Modified: 2026-11-18
- Do: Owner request, 2026-11-17: keep the data in third normal form at least, starting with the first. A field holds one domain in every row ([theory](../../theory/normal-forms.md#first-normal-form-1nf-one-value-of-one-kind-per-field)). Today one field breaks it: a perk prerequisite's `skills[].id` is a single ref in 59 rows and a list of refs ("any of these") in 10, and `label` follows it as a parallel list. `feature.schema.json` allows both, and `backend/internal/data/data.go` (`SkillRequirement.UnmarshalJSON`) reads both. [V 2026-11-17]
  - **One shape:** every skill requirement names a list, `skills: [ref, ...]` with `min`, met when any one listed skill reads at least `min`; a single skill is a list of one [A]. The spec step may pick another single shape (for example `skill` beside `any_of`), as long as each field keeps one type.
  - **The parallel `label` list goes** with the field it pairs with. Dropping the single labels too is M5-71; this issue may do both in one edit of those rows if M5-71 is not started, and say so in its decision record.
  - **The gate:** a test walks every file under `ruleset/data/` and `ruleset/modules/` and fails when one field path holds two JSON types across rows (null aside, integer and float counted as one). It lists the paths it found. Add it as a normal-form section of `docs/core/integrity.md`.
