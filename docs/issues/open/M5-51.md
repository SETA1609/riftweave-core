#### M5-51 One JSON format, checked in CI
- Status: todo
- Priority: medium
- Needs:
- Do: Owner request, 2026-11-15: the data is hard to read. Of 136 data files, 80 put each row on one line (many past 140 columns), 25 put every field on its own line, and 31 mix both; nothing checks it. Keep plain JSON: JSON5 or YAML would need a parser in every reader (validate.py and jsonschema, the Go loader, the WebAssembly build, the frontend fetching from GitHub, editors checking `$schema`, other engines), and a build step to JSON would leave two copies [A]. Add a stdlib-only formatter, `ruleset/scripts/format_json.py`, run by `scripts/format-json.sh` (writes) and `--check` (lists the files it would change, exits non-zero). Rules: 2-space indent; an object or array that fits in 100 columns at its indent stays on one line with a space inside the braces (`{ "target": "hp", "op": "add", "value": 15 }`), else one member per line; key order as written; strings never wrapped, so a long description may pass 100 columns; UTF-8 kept (no `\u` escapes); one trailing newline. Formatting a formatted file changes nothing. The Validate ruleset workflow runs `--check` on the paths listed in `ruleset/scripts/format_paths.txt`. This issue adds the tool and the check only; the list starts empty, so no file is reformatted here (the 44 schemas and 22 vectors alone are over 20 files). M5-52 formats the files.
