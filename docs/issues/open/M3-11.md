#### M3-11 One rule set for turn-based and real-time play
- Status: todo
- Priority: high
- Needs: M2-07, M2-08
- Do: There is one set of rules, yet the data still carries per-mode columns and the two modes have no defined conversion. Mana pays for everything magical in both modes, auras included. AP pays for actions at a table and stamina pays for physical actions in real time, so an action keeps one cost. Add two values to the data: `seconds_per_turn` = 5, so `turns = ceil(duration / seconds_per_turn)` and a per-turn tick is magnitude times the seconds that turn covers, which keeps an over-time total the same in both modes; and `stamina_per_ap` (proposal 5 [A]), so a real-time action costs its AP times that much stamina. At a table, an effect that restores stamina restores AP at stamina divided by `stamina_per_ap`. That AP arrives at the start of the actor's next turn, never the current one, and the pool stays capped by its `cap` of 10 [A]; without this a Stamina Potion (30 stamina is 6 AP, for an `item` costing 2) or Vigor (20 is 4 AP, for a `cast` costing 3) would pay for itself and a turn would never end. Food is out of combat (M2-07), so at a table it fills the carried pool before a fight. No separate one-item-per-turn cap: delayed AP removes the loop, and potion toxicity (M2-09) limits repeat drinking. A modifier's `turns` and an effect's seconds use the same conversion. Replace the `ttrpg` and `video_game` text on the 24 conditions with shared modifier rows. Move the `videoGame` block out of core, since i-frames and parry windows are presentation. Remove `cost.stamina` from spells. Clean the module docs of separate modes and leave one stamina formula, M2-08's `10 + END × 5 + level × 2`.
