#### APP-28 One set of i18next locale files for the frontend and the human CLI
- Status: todo
- Priority: medium
- Needs: APP-24, APP-26
- Modified: 2026-11-16
- Do: Owner request, 2026-11-16: the CLI speaks the same languages as the frontend, from the same files. APP-24's `frontend/src/locales/<lng>.json` move to one shared place, `locales/<lng>.json` at the repo root [A], that the frontend bundles (an `angular.json` asset or a JSON import) and the CLI embeds (copied into the Go module by the build, as the WASM build does with the ruleset, with a test that the copies match [A]). The files are i18next JSON v4 limited to what both sides read: nested keys, `{{name}}` interpolation, and plural keys with `_one` / `_other` (and the other CLDR suffixes a language needs). No `$t()` nesting, formatters, or context suffixes [A]; a test in both apps refuses a file that uses them. The Go side is a small reader in `backend/internal/i18n` over `golang.org/x/text` (already a dependency) for the plural rules, no new package [A]. The CLI's menus (APP-26), labels, and messages move to keys; the language comes from `settings.locale` (APP-25), else `LANG`, else English, and a missing key falls back to English. Review: German and Spanish are reviewed by the owner; other contributors may add or change other languages (as APP-24). Ruleset content stays as the data writes it.
