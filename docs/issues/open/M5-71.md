#### M5-71 Second normal form: a reference is the key alone
- Status: todo
- Priority: medium
- Needs: M5-70
- Modified: 2026-11-17
- Do: Owner request, 2026-11-17. A nested list is a child table keyed by its parent and the item it names, so a field there that is a fact about the item alone breaks second normal form ([theory](../../theory/normal-forms.md#second-normal-form-2nf-no-fact-about-part-of-the-key)). Today 77 references carry a copy of the target's `label`: 59 in perk prerequisites (`features/core.json`, `prerequisite.skills[]`) and 18 in race `traits` (`races/core.json`). Four are already stale: M5-56 renamed `block` to `shields`, and four prerequisites still say "Block". [V 2026-11-17] The schema says the label "is duplicated for readability". The 2026-11-01 review flagged the race copies as DOD-23.
  - **Drop every copied field** beside a reference: the 77 labels, and any other field that repeats the target row.
  - **Consumers read the target:** the backend, the CLIs, the frontend sheet, and the printouts show a prerequisite or trait by looking up the referenced row's `label` (for a module override, the overriding row's).
  - **The gate:** `validate.py` fails when an object that holds a `core:` reference also holds a field with the same name and value as a field of the referenced row (`label`, `description`, `phase`, ...) [A]. Fields that are about the pair, such as `min` or `rank`, stay. Add it to the normal-form section of `docs/core/integrity.md`.
