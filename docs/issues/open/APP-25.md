#### APP-25 One settings file that both apps read, export, and import

- Do: Owner request, 2026-11-16: the Angular app and the human CLI (`riftweave play`) hold the same settings and can trade them: settings exported from the frontend import into the CLI, and the other way round. Define the file once as a JSON Schema, `backend/contract/settings.json`, beside the command contract: `{"riftweave": "settings", "version": 1, "locale", "theme", "modules", "network", "bestiary"}` [A]. `locale` is an i18next language code (APP-24, APP-28); `theme` is `light`, `dark`, or `system` (APP-23; the CLI maps it to its Lip Gloss colours (owner, 2026-11-16)); `modules` lists the enabled module ids from `ruleset/modules/*/manifest.json`; `network` is `{"mode": "local" (offline, the default) | "server" | "room", "server_url", "room_code"}` (room is shown, disabled, until APP-17); `bestiary` holds APP-29's reveal setting. A key one app does not use is kept on import and written back on export, so a round trip loses nothing [A]; an unknown `version` is refused with a message. **Frontend:** `AppContext` (APP-23) is the one source; it saves to `localStorage` as APP-23 does, and the settings screen (APP-27) has "Export settings" (downloads `riftweave-settings.json`) and "Import settings" (file pick, validated against the schema before it applies). **CLI:** settings live in `os.UserConfigDir()/riftweave/settings.json`; `riftweave settings export [file]` and `riftweave settings import <file>` do the same, and the play TUI's settings screen (APP-26) reads it. The enabled modules change what the core loads (owner, 2026-11-16): `core.Open` gains a module selection, and the ruleset loaded is core plus the enabled modules only. Core is always loaded and cannot be turned off; `modules` lists optional modules only, and a file that lists `core` there is refused (owner, 2026-11-16) [U: whether `core.Open` can load a subset today is not checked]. Because two devices with different modules load different data, every exported file and session names its enabled modules and their versions (APP-30), and an import or update that would drop data of a module this device does not load is stopped with an alert naming the module and what would be lost, never dropped silently (owner, 2026-11-16).
