#### M5-73 Third normal form: an override lists only what differs
- Status: done
- Merged: #225, 2026-11-17
- Priority: medium
- Needs: —
- Modified: 2026-11-17
- Do: Owner request, 2026-11-17. An override row names a `base` and should list only the fields that differ; a value equal to the base's is a fact about the base, copied ([theory](../../theory/normal-forms.md#third-normal-form-3nf-no-fact-about-another-non-key-field)). Today, in equipment and monster overrides, 74 fields equal the base field they replace (`phase` 26, `size` 24, `tags` 9, `level` 7, `hitPoints` 6, `enchantment_slots` 2), and 4 subraces repeat their parent race's `phase`. [V 2026-11-17]
  - **Drop the copies,** so each override reads as its differences.
  - **Whole-object overrides:** the merge (`_merge_field` in `validate.py`, and the Go loader) replaces an object whole, so changing `cost.quantity` forces `cost.unit` to be repeated; 41 such values exist (`cost` 15, `accessory` 10, `attributes` 16). [V 2026-11-17] Decide in the spec step whether objects merge field by field [A: yes, with `$extend` kept for lists] and update `docs/core/overrides.md` and both loaders the same way, with a vector.
  - **The gate:** `validate.py` fails an override field (or, with a field-by-field merge, a sub-field) equal to its base, and a subrace field equal to its parent's. Add it to the normal-form section of `docs/core/integrity.md`.
