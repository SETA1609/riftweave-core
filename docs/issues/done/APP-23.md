#### APP-23 An app context with a light and dark mode toggle
- Status: done
- Merged: #204, 2026-11-16
- Priority: medium
- Needs: APP-19
- Modified: 2026-11-16
- Do: Owner request, 2026-11-15: the app holds its mode and its language in one context. Add `AppContext` (`frontend/src/app/context.ts`), a root service of signals, the one place a screen reads the viewer's settings: `theme` (`light`, `dark`, or `system`) here, and `locale` for APP-24. It starts from the saved choice, else the system (`prefers-color-scheme`), and saves each change in `localStorage` (a per-viewer convenience; APP-16 may move it to IndexedDB), with every read and write in try/catch so a blocked storage still renders. The theme is applied as `data-theme` on `<html>`: `styles.css` keeps its tokens, moves the dark ones under `:root[data-theme="dark"]`, and keeps the `prefers-color-scheme: dark` block for `system` only, guarded by `:root:not([data-theme="light"])`. A reusable `rw-theme-toggle` (ui/, split `.ts`/`.html`/`.css`) in the header cycles light, dark, and system, with an `aria-label` that names the next mode. No component reads `localStorage` or `matchMedia` itself. Owner rule, 2026-11-15: components, services, pipes, and directives are generated with the Angular CLI (`npx ng generate component ui/theme-toggle`, `npx ng generate service context`) and then filled in, not written from scratch; write the rule in `docs/backend/frontend.md#conventions` with the commands, and generate `AppContext` and `rw-theme-toggle` that way. Keep a generated `*.spec.ts` only where it holds a real spec; the shared specs stay in `app.spec.ts`.
