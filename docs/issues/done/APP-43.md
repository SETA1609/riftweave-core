#### APP-43 Telemetry in the OpenTelemetry format, and a telemetry setting both apps share

- Do: Owner request, 2026-11-18: one format for what every component reports, so a trace from the frontend through the server reads as one, and an exported diagnostics file reads the same from any app. The format is OpenTelemetry's: logs, traces, and metrics in its data model, written as OTLP/JSON, with its semantic conventions ([A]: `service.name` is `riftweave-server`, `riftweave-cli`, `riftweave-play`, or `riftweave-web`; `service.version` the build; `riftweave.rules_version` the rules; a command is the span `riftweave.command <name>` with `riftweave.command.name`, its duration, and `error.type` on a refusal). Write it down in a new `docs/backend/observability.md` with the attributes each component sets.
  - **The core stays pure.** No telemetry package is imported by `backend/core` or `backend/internal/`; a test fails if one is, as `TestCharmStaysOutOfTheCore` does for Charm. The adapters (server, CLIs, frontend) observe the calls they make.
  - **Nothing about the player.** An event names the command, its duration, its outcome, and the error kind, never an actor, a session, a save, or a free-text input [A].
  - **Offline first.** A new `telemetry` key in the settings file (APP-25, `backend/contract/settings.schema.json`): `mode` is `off` (the default), `local` (kept on the device, exportable as a diagnostics file), or `export` (sent to `endpoint` by OTLP/HTTP). Both apps read and write it with the same rules, and the shared fixture gains it.
  - Export follows OpenTelemetry's environment variables where a process has them (`OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_SERVICE_NAME`, `OTEL_SDK_DISABLED`) [A].
- Keys: the `telemetry` settings key; the `riftweave.*` attributes
- Files: ~6 (docs/backend/observability.md, docs/backend/settings.md, backend/contract/settings.schema.json, backend/internal/settings/settings.go, frontend/src/app/settings-file.ts, ruleset/tests/fixtures/settings/settings.json)
- See: docs/backend/settings.md, https://opentelemetry.io/docs/specs/otel/ (cite through `fetch-docs`), docs/issues/open/APP-44.md
