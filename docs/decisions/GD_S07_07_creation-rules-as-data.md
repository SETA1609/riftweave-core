# GD_S07_07_creation-rules-as-data The character creation numbers as data

Date: 2026-11-20

- **Decision:** the point-buy and the creation-perk cap move from prose into a `creation` block of `ruleset/data/progression/core.json`: `attribute_start` 4, `attribute_points` 10, `attribute_max` 10, `creation_perks_max` 2, unchanged from docs/modules/character-creation.md (owner kept 4 + 10 on 2026-11-19, [PO_S08_09](PO_S08_09_file-compendium-creation-form-issues.md)). The rule is in docs/core/progression.md#character-creation; character-creation.md quotes the numbers and links to the data. [V 2026-11-20, `progression` vectors, op `point_buy`]
- **Tag skills, the pool, and the base ratings stay where they are:** `tag_skills` (3), `skill_points`, and `skill_start` were already in `progression`, so the `creation` block does not copy them; the docs name them. Moving `tag_skills` into `creation` would rename a key, which is breaking and its own issue (CONTRIBUTING.md#naming). The issue's key list put `tag_skills` in the block as an [A]; this replaces that.
- **A check, `point_buy`:** the `progression` command gains the operation `point_buy`, in Python (`kernel_reference.py`) and Go (`backend/internal/progression`), so a vector can reject a bad point-buy and the creation command (`BE_S07_08_character-creation-command`) and the form (`FE_S07_09_character-creation-cv-form`) read the same check. It takes `actor.attributes` as assigned, before race and creation perks, and returns `spent` and `left`, the names `spend` already returns. An attribute missing, under `attribute_start`, or over `attribute_max` is an error, checked in ability order before the total; more than `attribute_points` spent is an error. Fewer is not an error, so a draft can be checked step by step; a finished build must leave 0. [A]
- **The build checker reads the data:** `build_reference.py` takes the point-buy and the creation-perk cap from `creation` instead of constants, and runs the same check, so a change to the numbers is seen by every suggested build. Every build still passes. [V 2026-11-20, `test_builds.py`]
- **Open:** whether `creation_perks_max` should become a modifier target, so Human Ambition (the option of one more perk) is data too [U]; it stays prose (docs/modules/character-creation.md step 7). The creation command decides how a draft reports `left > 0` [A].
