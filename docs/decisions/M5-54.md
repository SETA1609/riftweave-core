# M5-54 Theory: string keys, hashing, and interning

Date: 2026-11-15
Modified: 2026-11-15

- **Decision:** the data, saves, the command contract, the API, and modules keep string keys.
  Programs intern them into dense per-category indices once at load and never write an index
  out; a hash is acceptable only with a collision check at load. The explanation is in
  `docs/theory/keys.md`; the rule in `docs/core/keys.md` is unchanged.
- **Why:** the data-oriented advice against string ids is about memory in a hot loop, not the
  file format, and M5-29 and M5-30 already removed numeric row ids for readability, module
  safety, and stable saves. The Go loader already interns (`data.Table`).
  **[V 2026-11-15, `backend/internal/data/data.go`]**
- **Open:** the cost of per-request string lookups in the backend is assumed negligible, not
  profiled **[A]**. Typed per-category index types (`type WeaponIndex int32`) are recommended,
  not adopted in the Go code.
- **Risk:** none; documentation only.
