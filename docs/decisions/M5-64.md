# M5-64 Composition drawn as class diagrams: bases, templates, and kinds

Date: 2026-11-18

- **Decision:** `data_model_diagram.py --write` also writes `docs/core/composition-diagram.md`: per composing collection, a `classDiagram` of its shape (the row as written, each kind of base, and the row that names a base, with their fields) and one of its instances from the data (which rows build on which base). Then the monster templates, one class per `slot`. [V 2026-11-18, `test_data_model_diagram.py`]
- **Read, not listed:** a family is any collection whose items are `oneOf` a full row and a row with `base` and `overrides`; the base kinds come from the categories in the `base` reference's pattern, and the fields through `allOf`, `oneOf`, `anyOf`, and `$ref`. Today that finds equipment (weapon, armor, and accessory bases), monsters (a creature type or a monster), and spells (a spell). A test fails if the set changes without the page.
- **Capped instances** [A]: the 10 most used bases of a family, with up to 3 rows each and a note counting the rest, so 59 monsters stay readable.
- **Perk kinds** wait for M5-58: the page says so while `feature.schema.json` has no `basePerk`, and a test ties the line to that check.
- **Open:** the blocks were not rendered by Mermaid in this change (the local render was not run) [U]; they use `class X["label"]`, `<|--`, `..>`, and `note for`, which Mermaid 10 and later document.
