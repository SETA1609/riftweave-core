# M5-51 One JSON format, checked in CI

Date: 2026-11-15
Modified: 2026-11-15

- **Decision:** the data stays plain JSON, laid out by one stdlib formatter,
  `ruleset/scripts/format_json.py`: 2-space indent, one line when the one-line form fits in 100
  columns (counting indent, key, and comma), otherwise one member per line; nothing reordered or
  rewritten. CI runs `--check` on the paths in `ruleset/scripts/format_paths.txt`. The rule is in
  `CONTRIBUTING.md#json-format`. **[V 2026-11-15, `test_format_json.py`]**
- **Why plain JSON:** JSON5 or YAML would need a parser in every reader (the validator, the Go
  loader, the browser build, editors checking `$schema`, other engines). **[A]**
- **Why numbers keep their spelling:** the formatter parses numbers as the text the file has,
  so `1.0`, `0.50`, and `1e3` survive; M5-52 can then format a file with a diff that changes
  only whitespace. A test runs the formatter over every tracked JSON file (182 would change
  today) and checks the parsed values are equal and a second run changes nothing.
  **[V 2026-11-15]**
- **Difference from the issue:** no schema step, since the issue adds a tool and changes no
  data shape; the steps are spec, test, tool, and review. The shim was not run, because the
  toolchain container did not start on this host; the script itself ran and the devops-tools
  config parsed. **[U]**
- **Open:** a modifier at indent 8 with five fields passes 100 columns and breaks one field
  per line; if that reads too long in the perk file, M5-52 can raise the width. **[A]**
