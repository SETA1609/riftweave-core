# DE_S02_01_one-property-casing One property casing

Date: 2026-11-20

- **Decision:** `snake_case`, the casing of entry keys and of the newer schemas. `CONTRIBUTING.md#naming` now says every property is `snake_case`. `validate.py` (`check_property_casing`) and `test_integrity.py` (`TestOnePropertyCasing`) fail a camelCase property declared or required in a schema, and any camelCase key in a data file: core, bases, and every file under `ruleset/modules/`, manifests included. JSON Schema keywords (`additionalProperties`, `oneOf`) and `$ref` definition names are not properties. [V 2026-11-20]
- **Count:** the issue's 72 counts camelCase names across schemas with repeats. There were 37 distinct camelCase property names in `ruleset/schemas/` and the same set in the data; the backend contracts and the golden vectors had none. [V 2026-11-20, a scan of every `properties` and `required` and every data key]
- **Renamed (35):** `abilityModifiers`, `accessoryType`, `appliedBy`, `associatedAbility`, `attackReach`, `baseChance`, `baseCost`, `coreDrop`, `damagePerLevel`, `defaultDuration`, `defaultDurationType`, `defaultFor`, `drBase`, `durationType`, `effectMagnitude`, `evasionPenalty`, `foundAs`, `loadAfter`, `magnitudeMultiplier`, `magnitudeUnit`, `maxGrade`, `maxStacks`, `minGrade`, `parentRace`, `perLevel`, `qualityGrade` (the ingredient property), `rangeLong`, `rangeNormal`, `removedBy`, `requiresLayer`, `speedPenalty`, `stealthPenalty`, `strengthRequirement`, `valueFactor`, `weightFactor`. Each becomes its `snake_case` form (`dr_base`, `parent_race`, ...), in schemas, data, module data, the Python reference and tests, the Go `json` tags, and the docs.
- **Not renamed:** `hitPoints` and `hitPointsPerLevel`, which DE_S02_03 (#397) removes. `check_property_casing` allows the two by name (`CAMEL_CASE_ALLOWED`) until then. The allowance should go when this branch is rebased on DE_S02_03. [A] Definition names in `schema.json` (`qualityGrade`, `diceExpression`, `damageType`, `appliedEffect`, `sourceRef`, the `*Ref` types) stay. They are `$ref` targets, not properties, and the docs name the `qualityGrade` vocabulary by its definition. [A]
- **A Go reader that matched by case:** `materials/core.json` was read into an untagged `ValueFactor` field, which `encoding/json` matched case-insensitively to `valueFactor`. It now has `json:"value_factor"`. A search found no other untagged field with a renamed name. [V 2026-11-20, `go test ./...` loot vectors]
- **History left as written:** `CHANGELOG.md`, `docs/archive/`, `docs/decisions/`, `docs/issues/`, `changes/`, and `docs/playtests/`. They record what was true when they were written. Open issue files that name an old key (for example GD_S17_03, GD_S07_07) are left for their own PRs. [A]
- **Size:** 55 counted files, over the 20 of CONTRIBUTING.md rule 2. A key rename has to land in the schema, the data, and every reader at once, or `validate.py` and the tests go red (rule 3). The issue's own split, by collection, would give one PR per collection (equipment, monsters, effects and conditions, races and skills, materials), each green, with the gate in the last one. The owner asked for one PR per S02 issue, so this is one PR of mechanical renames. Every change is a word-boundary rename of the 35 names, and the hand edits are the gate, its tests, the Go tag, the `qualityGrade` lines, and CONTRIBUTING. [A]
- **Risk:** **breaking**: a module or a save that writes an old key fails validation, or its value is ignored. `frontend/src/api/openapi.d.ts` is not regenerated (it needs a running server), as in GD_S05_01, so it still shows `durationType`. No frontend code reads it.
