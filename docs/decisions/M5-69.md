# M5-69 File the normal-form issues, with the theory page

Date: 2026-11-17

- **Decision:** the source data is kept in third normal form at least. `docs/theory/normal-forms.md` explains 1NF to 3NF and how they read for JSON rows. Six issues fix what the audit found, each adding a gate to `docs/core/integrity.md`: M5-70 (1NF), M5-71 (2NF), M5-72 (domains), M5-73, M5-74, and M5-75 (3NF). Owner request, 2026-11-17.
- **How 1NF reads for JSON** [A]: a nested list owned by one row is a child table (keyed by the parent plus the item) and is allowed. A field whose type changes between rows, parallel lists, and several facts in one string are not.
- **Generated copies are allowed:** the runtime tables, generated docs, playtest reports, and vectors copy on purpose and are not edited as facts.
- **The audit** ran scripts over every file in `ruleset/data/` on `main` at `c99c7a8`. [V 2026-11-17]
  - 1NF: one field path of two types, `features[].prerequisite.skills[].id` (59 refs, 10 lists), with its parallel `label`.
  - 2NF: 77 labels copied beside references (59 in perk prerequisites, 18 in race traits), 4 of them stale ("Block" for `core:skill/shields`).
  - Domains: the ability enum in `schema.json`, `derived.schema.json`, and `ability.schema.json` beside `abilities/core.json`; the damage-type enum beside `combat/damage_types.json`.
  - 3NF: 74 override fields equal to their base; 4 subraces repeating the parent's `phase`; 41 values repeated because an override replaces a whole object; 55 of 59 monsters storing `hitPoints`; 79 of 124 feature descriptions restating a modifier number (a text match, so a few may be coincidences).
  - Already normal: applied effects copy no field of their effect row; a spell stores `color`, not its skill; the armor casting penalty lives once per weight class.
- **Sources:** Kent 1983 and three Wikipedia articles, fetched into `cache/docs/` on 2026-11-17. Codd's 1970 and 1971 papers are quoted only through Wikipedia. [U]
