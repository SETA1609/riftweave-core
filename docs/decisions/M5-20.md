# M5-20 Wuxing becomes a module, the reference for cross-cutting modules

Date: 2026-11-11

- **Decision:** the cycles, vectors, and phase-coverage test live in `ruleset/modules/wuxing/`. Core keeps `phase` as an optional tag, and no core rule reads it. Spec: `docs/modules/wuxing.md`, `docs/modules/module-system.md#worked-example-wuxing`. **[V 2026-11-11, validate, unit tests, and core vectors with the module on and off, in Python and Go]**
- **Decision:** `core.Open` loads every module beside `ruleset/data`, and `core.New` loads only those it is given, so a caller can run with none. **[A]**
- **Decision:** the `wuxing` command stays in the contract, and with the module off it is a rule error. **[A]**
- **Why:** the contract calls Wuxing a module, but core required `phase` and shipped the cycles.
- **Difference from the issue:** the module's effect on an attack or a cast is written as a rule (a consumer emits `mul`), but no consumer emits it yet, because no core system reads a phase. **[U]**
- **Open:** the Go backend reads only the Wuxing module's data; other modules load their manifest and nothing more. **[A]**
- **Risk:** `combat_reference.py` and `crafting_reference.py` still import Wuxing directly; they are not core rules and nothing runs them. **[U]**
