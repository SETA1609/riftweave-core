# M5-62 One project version, and a release that tags it

Date: 2026-11-17

- **Decision:** `VERSION` at the repo root is the one version, `0.1.0`. The Go core embeds a copy that `go generate ./core` writes to `backend/core/VERSION` (chosen over `-ldflags`, because every build path, `go test`, the WebAssembly build, `app.sh`, and the container, would need the flag, and one that forgot it would silently report a default). `core.RulesVersion` becomes a variable read from the embed. `frontend/package.json` (and its lockfile) and the `author` module manifest say `0.1.0` too. [A in the issue, chosen here]
- **The test:** `TestTheVersionIsTheRepoVersion` fails when the embedded copy or `frontend/package.json` differs from `VERSION`; `TestTheAuthorManifestStartsAtTheVersion` fails when an exported manifest or its fixture does. [V 2026-11-17, `go test ./core`]
- **The release check** is a tested script, `ruleset/scripts/release_check.py`, not workflow shell: the tag must be `v` plus `VERSION`, `CHANGELOG.md` must have its `## v<version>` section, and every key `key_diff.py` reports as removed since the previous tag must be named in a **(breaking)** bullet of that section. It also writes the section as the release notes. [V 2026-11-17, `test_release_check.py`]
- **The workflow:** `.github/workflows/release.yml` runs on `v*` tags, reads the tag only through `env:`, pins `actions/checkout` by commit, and creates the release with `gh release create --verify-tag`. `pages.yml` (APP-15) already publishes on the same tag; it does not wait for the release check. [A] If a failed check should also stop the app from publishing, Pages could run on `release: published` instead; owner question.
- **The branch flow** follows M5-76: the release branch starts from `development`, merges there, then `development` merges into `main`, and the owner tags the merge commit on `main`.
- **Not done here (owner steps):** tagging `v0.1.0`. The first release needs the fragments released into a `## v0.1.0` section first, which is the release pull request, not this one.
