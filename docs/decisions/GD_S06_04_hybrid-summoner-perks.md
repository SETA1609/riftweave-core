# GD_S06_04_hybrid-summoner-perks Hybrid summoner perks: a spellblade or arcane archer fights beside their summons

Date: 2026-11-19

- **Decision:** the hybrid summoner's perks are attribute bonuses with the `while_summoning` duration (live only while the holder has an active summon; GD_S06_02 uses it too), in two paths: melee (Bonded Vanguard, then Vanguard Ascendant: STR and END) and ranged (Bonded Marksman, then Marksman Ascendant: AGI and PER), plus Kindred Mind (INT and WIL) for both, and Pincer Strike (+10 to attack beside a summon). [A, the issue left the attributes to the spec]
- **`modifiers` reads `summoning`:** an attribute bonus is read through the generic `modifiers` function, which knew nothing of summons, so it gains an optional `summoning` input; absent is false and drops every `while_summoning` modifier. [A]
- **Striking together is a situation:** positions are the caller's (docs/core/combat.md), so `beside_summon` is a caller-named row of `situations.json` with no modifier of its own and a new field, `adds: beside_summon_attack`: while a row with `adds` applies, the attacker's modifiers on that target join the attack, and outside it they add nothing. It works at every range, unlike `flanking`, so the ranged path has it too. [A]
- **Mounts** are written in the spec as a later extension (a summoned steed and a mounted bonus) and not built.
- **Numbers** (+1 per attribute per tier, +10, levels 6, 10, 12, 18) are [A] until a playtest.
- **Why `adds`:** the attack roll sums every `add` modifier it is given, whatever its target, so a perk's bonus passed as an attack modifier would count without the summon; combat now holds back modifiers on any row's `adds` target until that row applies. The situation schema took the field rather than a row with no modifiers at all. [V 2026-11-19, `combat` vectors]
- **Verified:** the 4 `modifiers` and 4 `combat` hybrid vectors pass in Python (420 tests) and Go (`go test ./...`); `validate.py` passes 52 of 52 files. [V 2026-11-19]
- **Differences from the issue:** `backend/contract/modifiers.json`, `ruleset/schemas/situation.schema.json`, `ruleset/data/combat/situations.json`, `kernel_reference.py`, Go (`core/core.go`, `internal/combat`, `internal/data`), `docs/core/combat.md`, `docs/core/modifier.md`, `docs/core/vectors.md`, and the regenerated diagrams are files the issue did not list; `test_perks.py` needed no change.
- **Branch:** made from `development`, on its own. It carries the `while_summoning` foundation (the schema value, `modifier.Summoning` / `summoning_modifiers`, and the shared live step) line for line as GD_S06_02 does, so the two merge in either order; whichever lands second keeps only its own perks.
