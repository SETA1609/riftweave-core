# M4-08 Drops live on the monster, with defaults from the creature type

Date: 2026-11-11

- **Decision:** loot resolves from the creature type or base monster, then templates, then the row, then a `drops` row. Spec: `docs/core/loot.md#drops`. **[V 2026-11-11, `loot` vectors in Python and Go, `test_loot.py`]**
- **Decision:** `rolls_by_level` is `1 + level / 10`, rounded down. **[A]** Below level 10 a row that rolled a two-roll hoard writes `rolls: 2`, so its value does not change.
- **Decision:** type defaults are `grave_goods` for undead, oozes, and familiars; `bandit_purse` for humanoids; `beast_den` for beasts and plants; `hoard_minor` for constructs and elementals. **[A]**
- **Why:** every new monster needed a second edit in the loot file, and a derived monster could not inherit its parent's drop.
- **Difference from the issue:** monsters at level 20 and above now roll their hoards 3 or 4 times where they rolled twice, except `iron_colossus`, whose vector pins two. All of them still fit the budget. **[V 2026-11-11, `test_loot.py`]**
- **Difference from the issue:** 41 of the 54 rows still write `loot`, because their drops differ from their type's on purpose.
- **Open:** a template row is covered by a Python test only, since no core template has loot yet. **[A]**
