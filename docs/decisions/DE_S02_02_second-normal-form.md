# DE_S02_02_second-normal-form Second normal form: a reference is the key alone

Date: 2026-11-20

- **Decision:** gate 8 in `docs/core/integrity.md`. `validate.py` (`check_reference_copies`) fails an object that holds a `core:` reference and also a field with the same name and value as a field of the row it names. Only the referenced row's `key` is exempt (it is the identity), so `label`, `description`, `phase`, and any other field count. The named row is read after composition: an equipment item with its base merged, a creature type as its base file. Data files, base files, and module data are walked; golden vectors are inputs and are not. [V 2026-11-20, `test_integrity.py`]
- **What it found today:** the 59 perk prerequisite labels the issue counted were already gone (M5-70 made a skill requirement `{ any_of, min }`, [V 2026-11-20]). The gate found 46 copied fields instead: 18 race trait labels, 19 monster attack labels and 2 attack phases that repeated their weapon row (natural weapons and carried weapons), and 7 phases in the 6 crafted items (an item's `phase` equal to its material's or base's, and each `engraving_jewel.phase` equal to its gem's). All are removed, and so are the two engraved items' own `phase` values, which the gate does not see because they repeat the gem's phase one level up. [V 2026-11-20]
- **Shapes:** a race trait is `{ "id" }`. A monster attack's `label` is optional and defaults to its weapon's label; its `phase` is optional and defaults to a carried weapon's phase. A crafted item has no `phase` property any more: its effective phase is the engraving gem's, else the material's, which `crafting_reference.py` already computed from the rows. [A] Attack labels that differ from the weapon's (`Rusty Blade`, `Short Sword`, `Tree Club`) stay, because they are facts about the attack.
- **Consumers:** nothing in the backend, the CLIs, or the frontend read a race trait label, so no screen loses one [V 2026-11-20, grep of `backend/`, `frontend/src/`]. The monster stat block (`print`, kind `monster`) printed `attack.label`; it now prints the natural weapon's label (read from `natural_weapons/core.json`) or the item's (`data.Item.Label`, new) when the attack has none, and the print contract no longer requires `label`. `monster_reference.attack_label` and `attack_phase` do the same in Python; `test_wuxing.py` reads an attack's phase through `attack_phase`. [V 2026-11-20, `go test ./core`, `test_wuxing.py`]
- **Open:** module overrides: a reference is compared with the core row it names; a module that overrides that row and copies the module row's label next to the reference is not caught yet. [U] Other derived crafted-item fields, `attack_bonus` and `defense_bonus` ("derived from material.weapon.attack"), are third normal form copies with a different name, so gate 8 does not see them; they are left for a later 3NF issue. [A]
- **Risk:** **breaking**: a consumer that read `traits[].label`, `attacks[].label`, or a crafted item's `phase` must read the named row. `frontend/src/api/openapi.d.ts` is not regenerated (it needs a running server), as in GD_S05_01.
