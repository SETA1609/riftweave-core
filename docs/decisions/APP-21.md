# APP-21 Scripts run the frontend locally or in a container

Date: 2026-11-14

- **Decision:** two scripts beside the toolchain shims in `scripts/`, not `devops-tools container` commands: the toolchain image carries only Python, and the app needs Go and Node. `app.sh` runs on the host with hot reload; `app-container.sh` needs only a container engine. [A]
- **Decision:** `app.sh` builds the server into `cache/app/`, writes the proxy config there for the chosen API port, and installs the frontend's packages (npm 11.21.1, `npm ci`) only when `node_modules` is missing or older than the lockfile. With a Node below 24.15 it runs Node 24.22.1 through `npx` for that run, rather than asking the user to change their Node. Its trap stops the server when the app stops. [V 2026-11-14, run on Node 24.7: the fallback, the build, the install, the page, the API through the proxy, and both processes gone after the stop]
- **Decision:** the image is three stages (Go, Node, nginx) and about 64 MB. nginx serves the built app, falls back to `index.html` for app routes, and proxies `/v1` and `/openapi.json` to the server on the loopback, so the page and the API share one origin and the server needs no CORS. The image carries `ruleset/schemas` beside the data, since the server builds its OpenAPI document from them. The entrypoint starts nginx only once the server answers, and exits when the server stops. [V 2026-11-14, docker 29.5: the page, an app route, `/openapi.json`, and the first combat vector's result]
- **Decision:** image names are fully qualified (`docker.io/library/...`, `localhost/riftweave-app:local`), since podman does not resolve short names; docker accepts them too. Base images are pinned to exact versions: golang 1.27.2, node 24.22.1, nginx 1.29.3. [V 2026-11-14]
- **Why:** owner request, 2026-11-14: one command to start the frontend locally or through a container.
- **Open:** the issue asks for a podman run. On this machine rootless podman 3.4 has no subordinate ids (`/etc/subuid` and `/etc/subgid` are empty), so it cannot unpack the base images, and the build was not completed. The script now detects that and prints the fix (`usermod --add-subuids`/`--add-subgids`, then `podman system migrate`); a podman run on a configured host is still to do. [U]
- **Risk:** shellcheck was not available here, so the scripts were checked with `bash -n`, `sh -n`, and real runs only.
