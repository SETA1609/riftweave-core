# M2-09 Potion toxicity limits repeat drinking

Date: 2026-11-11

- **Decision:** every `drink` row states `toxicity`: 0 for the cures (`antidote`, `potion_cure_disease`, so a cure is never blocked), 10 minor, 20 standard, 35 greater; the schema requires it on a drink and forbids it elsewhere. Spec: `docs/modules/equipment.md#toxicity`, `docs/core/modifier.md#toxicity`. **[A]** **[V 2026-11-11, `test_equipment.py`]**
- **Decision:** toxicity falls 1 a second (`rest/core.json`, `toxicity_decay`), 5 a turn, and a short or long rest empties it (`empty`, a new rest mode for toxicity only; owner decision 2026-11-12 for the short rest, since an hour of decay empties any toxicity and a table does not count seconds). **[A]** **[V 2026-11-11, `toxicity.json` vectors in Python and Go]**
- **Decision:** the limit is the derived row `toxicity_limit`, `20 + END × 5` (25 at END 1, 70 at END 10), named as M5-46 asks rather than `tox_cap`; `consume` reads it as `max.toxicity`. **[V 2026-11-11]**
- **Decision:** a drink over the limit is not refused: its effects land and `core:condition/overdosed` holds while toxicity stays above the limit. Overdosed halves `potion_magnitude` and costs 1 `speed`, and its `appliedBy` is empty because a rule applies it; the condition schema now allows that. **[A]**
- **Decision:** food adds no toxicity and does not speed the fall; its value is preparation before a fight and cheap recovery after one.
- **Why:** nothing limited potions, so they crowded out food.
- **Open:** the stored actor has no `toxicity` yet, so a session does not carry it between steps; a game passes it in `current`. Whether a dish should speed the fall is left for play. **[U]**
