# M5-70 First normal form: one kind of value per field

Date: 2026-11-18

- **Decision:** a perk's skill requirement is `{ "any_of": [ref, ...], "min": n }`, met when any one listed skill reads at least `min`; a perk that needs one skill lists one. Each field keeps one type in every row. [V 2026-11-18, `validate.py`, `test_integrity.py`]
- **Why `any_of` and not `skills`:** the issue suggested `skills: [ref, ...]`, and let the spec step pick another single shape. Inside `prerequisite.skills[]`, a second `skills` would read `prerequisite.skills[].skills`; `any_of` says what the list means. [A]
- **The labels went too:** the issue allowed it while M5-71 was not started. All 69 skill requirements lost their `label` (59 single, 10 lists), including the four stale "Block" labels M5-71 counts. M5-71 keeps the 18 race `traits` labels. [V 2026-11-18]
- **A second mixed field, found by the gate:** `prerequisite.perks[]` held a bare ref in 21 entries and a `{ perk, rank }` object in 2 (M3-14). The issue's gate fails on it, so it is fixed here too: every entry is `{ perk, rank }`, with `rank` left out for 1. No other field path in `ruleset/data/` (bases included) or the modules' data holds two types. [V 2026-11-18, `check_one_type_per_field`]
- **The gate:** `check_one_type_per_field` in `validate.py` (gate 7 of `docs/core/integrity.md`) runs in `validate.py` and in `test_integrity.py`. It reads paths from the collection, so a field is compared across every file of its collection. Golden vectors are inputs and are not walked.
- **Readers:** `kernel_reference.py`, `data_flowcharts.py`, the tests, and `backend/internal/data/data.go` read one shape each; the Go `UnmarshalJSON` for skills is gone (plain struct tags), and the one for perks reads only the object.
- **Not run here:** `go test ./...` for the packages that need module downloads (`backend/core`, `backend/mcp`, the commands); the sandbox has no network. `internal/` packages pass with a local toolchain; CI runs the rest. [U]
- **Risk:** breaking for anything that reads `prerequisite.skills[].id` or a bare-ref `prerequisite.perks[]` entry.
