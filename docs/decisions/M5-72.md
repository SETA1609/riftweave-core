# M5-72 A domain written once: enums and their tables

Date: 2026-11-18

- **Decision:** each shared enum lives once, in `schema.json`; `ability.schema.json`'s `id` and `derived.schema.json`'s `attribute` are now `$ref` to `schema.json#/definitions/ability`. A test fails when any other schema repeats one of the five shared enums. [V 2026-11-18, `test_integrity.py`, `validate.py`]
- **Enum and table agree, by a test** (as the issue proposed, so each schema stays readable alone): `ability` against `abilities/core.json`, `damageType` against `combat/damage_types.json`, `phase` against the wuxing module's `phases`, and `color` against the `*_magic` skills. All four agree today. [V 2026-11-18]
- **`color`, `phase`, and `qualityGrade` stay enum-only** [A]: a color is already a skill (`<color>_magic`), a phase is the wuxing module's row, and a grade has no field beyond its name. `tiers` is not the grade table: it is another scale (Common to Legendary, by `id`).
- **Open:** the `spellcraft` command contract (`backend/contract/spellcraft.json`) repeats the `color` enum twice. It is left for a change that also regenerates the contract diagram of APP-36, so the two pull requests do not make each other's generated page stale [U].
- Rule: docs/core/integrity.md#6-a-domain-is-written-once.
