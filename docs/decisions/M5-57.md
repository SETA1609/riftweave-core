# M5-57 Data model diagrams in Mermaid, generated from the schemas

Date: 2026-11-15
Modified: 2026-11-15

- **Decision:** the data model diagrams are generated, not drawn: `data_model_diagram.py` reads
  `ruleset/schemas/` and writes `docs/core/data-model-diagram.md`, Mermaid `erDiagram`s that
  GitHub renders. An entity is a collection of rows (a top-level array of objects); a line is a
  reference, found by its `core:<category>/` pattern, labelled with the fields that hold it, one
  line per pair of collections. `test_data_model_diagram.py` fails when the page differs from
  what the schemas give. **[V 2026-11-15: 43 collections, 61 pairs; all five diagrams parse with
  mermaid 11.4.1]**
- **Why generated:** a hand-drawn diagram drifts on the first schema change; this one is checked
  in CI with the unit tests.
- **Decision:** `overrides.` is dropped from a path (an override repeats its base's fields), and
  where two schemas name a collection alike, the one not named after it is prefixed with its file
  (`balance_tiers`, `material_form_recipes`).
- **Open:** a reference through the generic `namespacedRef` (an effect's `parameter`) names no
  single collection, so it is not drawn; nor are enum vocabularies (`ability`, `damageType`,
  `color`). The page's `Modified` date is a constant in the script, bumped with a change. **[A]**
