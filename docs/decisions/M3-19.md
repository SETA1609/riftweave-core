# M3-19 Commanding Summons has two ranks

Date: 2026-11-14

- **Decision:** the rule is data: each summon bonus row has `rank_share`, `[0.5, 1]`, and a held rank adds `floor(max(CHA − 5, 0) × rank_share[rank − 1])`. At CHA 8, +1 then +3; at CHA 10, +2 then +5; at CHA 6, 0 then +1. The floor at 0 comes before the share, as M3-13 floored the modifier. [V 2026-11-14, `test_spells.py`]
- **Decision:** both Commanding Summons perks have `ranks: 2`. A caster's perks may be bare refs (rank 1) or `{ "perk": ref, "rank": n }`, the same shape as a monster's perks (M3-15), so M3-13's callers keep working. [V 2026-11-14]
- **Decision:** M3-13's tests asserted +3 at CHA 8 for a held perk; that is now rank 2's value, and the tests say so. [V 2026-11-14]
- **Why:** owner request, 2026-11-14: the summoning CHA bonus grows in two steps.
- **Open:** the issue suggests a level or CHA prerequisite on rank 2; perk prerequisites are per perk, not per rank, so rank 2 needs only rank 1 for now. A per-rank prerequisite is a change to `feature.schema.json` for its own issue. [A]
