# M3-26 Spells compose from a base spell

Date: 2026-11-14

- **Decision:** a spell row is either a full spell or `spellWithBase`: `key`, `label`, `description`, optional `source`, `base` (a `core:spell/<key>` ref), and `overrides`, each override typed by the spell's own property (`#/definitions/spell/properties/<field>`), so the two shapes never drift. Resolution runs before the schema check, as for monsters and equipment, so the schema validates the flat row. [V 2026-11-14]
- **Decision:** an object field of the overrides (`cost`, `save`, and later M3-25's summon block) merges per field into the base's, on spells only; monsters and equipment keep their merge, so no existing row changes. Lists replace, or append with `$extend`, through `compose_row`. [V 2026-11-14, `test_spells.py`, `go test ./internal/data`]
- **Decision:** the row's `key`, `label`, `description`, and `source` are its own; the base's are dropped even when the row omits one, so a composed spell never shows its base's words. Since a flat spell needs a description, `spellWithBase` requires one. [V 2026-11-14]
- **Decision:** `greater_unlock` is the first composed row: `unlock` with its level, effects, and cost overridden. It casts exactly as the flat row did; the casting vector was written against the flat row and passes unchanged. [V 2026-11-14, `casting` vectors]
- **Decision:** every Python reader of `spells/core.json` (`casting_reference`, `hazard_reference`, `balance_report`, `playtest_driver`, and the `test_spells` loader) goes through `validate.load_spells`, and the Go loader resolves in `readSpells`, so no reader sees a raw composed row. `skill_audit.py` walks the raw file for each spell's color; a composed row inherits its color from a base that already counts it, so the audit is unchanged. [V 2026-11-14, `skill_audit.py --quiet`]
- **Why:** owner request, 2026-11-14: a spell should build on another and keep its qualities, first for M3-25's minion spells.
- **Open:** a base resolves only within the same file, so a module's spell cannot yet build on a core spell; that needs the module loader to pass the core spells in. [A]
- **Risk:** a reader that loads `spells/core.json` without `load_spells` sees `greater_unlock` without its color or level; the tests catch it only where they read spells. A new reader should use the helper.
