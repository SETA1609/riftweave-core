# M5-38 The stored actor has a schema

Date: 2026-11-11

- **Decision:** `stored_actor` in `backend/contract/common.json` is the one schema of what an actor stores. Spec: `docs/core/state.md#the-stored-actor`. **[V 2026-11-11, `stored_actor` vectors in Python and Go]**
- **Decision:** a session holds one actor, so the actor has no `id`, and pools use the derived keys, so stamina is `sp`. **[A]**
- **Decision:** an item instance has its own `id`, and `equipped` maps a slot to that id. Slot names are free keys until a slot table exists. **[A]**
- **Why:** the backend's actor had only attributes, skills, level, and growth, and APP-04 needs something to store.
- **Difference from the issue:** a `stored_actor` command was added, because a vector needs a function to run. Its round trip found that Go wrote a modifier's `op` as a number, now fixed.
- **Open:** `rest` still calls the stamina pool `stamina`; M5-37 (one word per concept) can settle the name. **[U]**
