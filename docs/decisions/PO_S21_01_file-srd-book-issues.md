# PO_S21_01_file-srd-book-issues File the generated SRD book issues

Date: 2026-11-21

- **Decision:** a new story, S21 Generated SRD (owner request, 2026-11-21): a PDF like the D&D 5.1 SRD, generated by code from the ruleset, never kept by hand.
  - **Content:** the outline and the player prose (`GD_S21_02`), and the entry layouts that the book and S09's print pages share (`GD_S21_03`).
  - **Code:** the generator (`DE_S21_04`), as the diagrams generated from the data are DE work, then the typesetting (`OPS_S21_05`) and the CI release (`OPS_S21_06`).
  - **Check:** coverage and clean text (`QA_S21_07`).
- **Why it fits:** the rules prose is in `docs/modules/` and `docs/core/`, and every number is in `ruleset/data/`. Gate 9 already keeps numbers out of descriptions, so the generator writes every number from the data [V 2026-11-21, ruleset/scripts/validate.py]. The content license is CC BY 4.0, the same as the D&D 5.1 SRD [V 2026-11-21, LICENSING.md].
- **Not tracked:** the PDF is built in CI and attached to the release, as generated files should be. The generated source goes to `build/`, which is ignored.
- **Assumed** [A], settled in the issues' spec steps:
  - Typst is the typesetter; `OPS_S21_05` compares it with Pandoc and LaTeX, and with HTML and a headless browser.
  - The builder's notes (`[V]/[A]/[U]`, issue ids, code links) are stripped, and a section that still reads badly gets a player version in `docs/srd/`.
  - The S09 print cards take their layout from `GD_S21_03`; no `Needs` edge is added, so S09 is not held back.
- **Open:**
  - One book, or a player book and a GM book?
  - Module appendices, or core only?
