# M5-41 A base with no changes is its own row

Date: 2026-11-11

- **Decision:** every equipment base states `is_item`. A base with `is_item: true` is also the item of its own key with no overrides, so `weapons.json` and `armor.json` hold a row only where it changes the base. Spec: `docs/core/composition.md#a-base-that-is-an-item`. **[V 2026-11-11, `test_composition.py`, `go test ./internal/data`]**
- **Decision:** 57 bases are items (34 weapons, 23 armor). 12 are shapes only: `bow` and `staff`, the armor bases `padded`, `plate`, and `scale_mail`, and the seven accessory `_base` files. A row that repeats an item base's key fails as a duplicate.
- **Decision:** one helper reads an equipment file's rows: `equipment_rows` in `validate.py` (the validator, the loot reference, the economy and equipment tests) and `itemBases` in the Go loader. Item bases come first, in file-name order. `is_item` is dropped from the resolved row, like `default_materials`.
- **Difference from the issue:** `gold_necklace` was the one other row with empty overrides (key `gold_necklace`, base `necklace_base`), so its resolved label read "Necklace". It now overrides `label` to "Gold Necklace"; that is the only change to a resolved item. **[V 2026-11-11, every resolved weapon, armor, and accessory compared before and after]**
- **Why:** a key was written twice for 57 items, once in the base and once in a row that changed nothing.
- **Risk:** a reader that loads `weapons.json` by hand and skips the helper misses 34 weapons. Every reader in the repo now uses it. **[V 2026-11-11]**
