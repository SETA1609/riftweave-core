# M5-14 Work the backend alongside the rules

Date: 2026-11-04

- **Decision (owner):** APP issues need only APP issues (and APP-01 the merged M1-02). The Go
  core starts with the commands that exist; from then on a rule issue that adds or changes a
  function updates the Python reference, the contract, and the Go core in the same pull
  request. Sessions grow with the commands instead of waiting for the playthrough chain.
- **Why:** a backend built after the rules would be a second pass over every rule; built
  alongside, each rule lands once in every place that implements it.
- **Replaces:** the M5-12 default that the Go core starts after M1 closes. The Python
  reference still stays the reference until 1.0.
- **Split by area (owner, 2026-11-04):** every rule PR now touches more files (reference,
  contract, Go). An issue that passes 20 counted files splits into
  `<issue-id>-ruleset-<slug>` and `<issue-id>-backend-<slug>`; the ruleset PR merges first and
  adds the changelog fragment, the backend PR adds a bullet to it. The issue id stays first in
  the branch name: the changelog check (devops-tools) reads it there, and
  `backend-<issue-id>-...` fails it. **[V 2026-11-04]** checked with `changelog-fragments
  check --branch` on both forms.
- **One branch form (owner, 2026-11-04):** agents no longer prefix branches with
  `agent/<name>/`; every branch is `<issue-id>-<slug>`. devops-tools still accepts the old prefix,
  so existing branches keep passing the changelog check until they are renamed.
