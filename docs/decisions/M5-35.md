# M5-35 A feature's bonus is written once

Date: 2026-11-12

- **Decision:** `modifiers` is the one statement of a feature's mechanics, and `description` says it in words ([progression.md](../modules/progression.md#what-a-perk-emits)). The `effects` list is gone from `feature.schema.json` and from every row, not reduced to text: on the 14 features that had both, every `effects` entry restated a modifier under another target name (`hp_max` against `hp`), and the description already said it. [V 2026-11-12, `test_perks`]
- **Decision:** the ten creation traits emit modifiers, source `feature:<key>`, origin `core:origin/trained`, as perks do. A number goes on an existing target where one fits (an attribute, `carry`, `tag_skills`, `animal_handling`, `poison_resistance`, `disease_resistance`) and on a new pending row otherwise (`skill_point_pool`, `starting_skill_points`, `ranged_attack_speed`, `undead_resistance`, `magic_resistance`, `spell_absorption_chance`). A restriction with no number is a `grant` of a pending flag whose description holds the rule: `afraid_of_undead`, `afraid_of_beasts`, `afraid_of_constructs`, `allergic_to_leather`, `allergic_to_iron`, `allergic_to_silver`, `cannot_aim`, `exotic_material_affinity`. [V 2026-11-12, `validate.py`]
- **Decision:** a phobia's penalty is the `frightened` condition (−10 on attacks and checks) while a creature of that type is in sight, the condition `core:effect/phobia` already applies. The old creation table's "−20% attack and damage vs undead" and "−15% vs constructs" were never in the data. [A]
- **Decision:** the seven effects only the traits named (`allergy`, `exotic_material_affinity`, `attack_speed`, `aimed_shots_restriction`, `skill_points_modifier`, `tag_skills_increase`, `carry_capacity_modifier`) are removed rather than marked reserved: they were a private language for one table, and nothing applies them. `phobia` stays, since `frightened` lists it in `appliedBy`. [V 2026-11-12]
- **Why:** two statements of one bonus had already drifted (DOD-11), and a creation trait's rule lived only in its prose.
- **Open:** `undead_phobia` gave 25% poison and disease resistance in the data, which its old description did not mention; it is kept and now written in the description. `iron_allergy` gave INT +1 in the data while its text said "+10% magnitude on magical effects"; the data's +1 INT is kept. `leather_allergy` listed END +1 twice (once as "comfort in metal armor"); one source, target, and op counts once under the stacking rule anyway, so it is one modifier now, and the old table's "+15% defense in metal armor" was never in the data. How much less an iron item gives an `allergic_to_iron` actor is not set. [A]
- **Risk:** the fourteen new targets are pending: no implementation applies them yet, so the traits' drawbacks are data a consumer must read until a kernel issue gives them vectors.
