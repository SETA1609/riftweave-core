# M5-37 One word per concept

Date: 2026-11-15
Modified: 2026-11-15

- **Decision:** coin units are spelled out, `copper`, `silver`, `gold`, and `platinum`, so `sp` is
  only the stamina pool; `CONTRIBUTING.md#naming` adds `sp` (stamina) to the allowed
  abbreviations and says coins are spelled out. A bonus on the attack roll targets the new
  `modifier_targets` row `attack_roll`, so `attack` is only the attack action's AP cost.
  **[V 2026-11-15, `validate.py`, the unit tests, and `go test ./...`]**
- **Why all four coins:** renaming only silver would leave `cp`, `silver`, `gp`, `pp`. Each file
  changes one line per cost, so 79 of the ~90 touched files stay under the counted-file limit.
- **Why the stamina `sp` stays:** it is in the stored actor, the command contract, and every
  session (`resources`, `growth`), so renaming it breaks saves and API clients; the coin unit
  is only in data and schemas.
- **Difference from the issue:** split. The four renames came to 25 counted files, over the
  limit of 20, so the monster field (`abilities` to `effects`) and the shield skill (`block` to
  `shields`) moved to M5-56 with their own PR.
- **Left as is:** the `_cp` suffix in `base_cp`, `price_cp`, `coins_cp`, `value_cp`, `budget_cp`
  and the economy result's `cp` mean copper only, so they are not ambiguous. Prose amounts
  (`100 gp`) in the module docs are display shorthand, not keys. **[A]**
- **Risk:** breaking for any data or client that names a coin unit; marked in the changelog.
