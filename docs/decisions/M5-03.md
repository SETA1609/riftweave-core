# M5-03 Move the container runner and agent image to devops-tools

Date: 2026-11-08

- **Decision:** the toolchain and agent containers come from devops-tools (`devops-tools
  container`, pinned in `tools/devops/pyproject.toml`), configured by
  `[tool.devops-tools.container]`: image `riftweave`, `container/Dockerfile`, the Python
  version from `.toolchain-python-version`, and the commands `validate`, `test`, and
  `python`. Every shim in `scripts/` is one `devops-tools container` call. The local `devops`
  package, its tests, `container/agent.Dockerfile`, and `container/entrypoint.sh` are gone.
  Spec: `tools/devops/README.md`. **[V 2026-11-08: `./scripts/container-image.sh`,
  `validate.sh` (45 of 45 files), `test.sh` (179 tests), `python.sh --version`, `shell.sh`
  under a pseudo-terminal, and `agent.sh true` all exit 0]**
- **Decision:** `container/Dockerfile` builds `FROM ${BASE_IMAGE}`, the devops-tools base, and
  adds only the pinned Python and the ruleset requirements in `/opt/riftweave-venv`.
- **Decision:** the toolchain Python moves from 3.13.18 to 3.13.12: the base image's uv
  (0.10.12) has no 3.13.18 build, and 3.13.12 is the Python the base already ships, so the
  image downloads none. **[V 2026-11-08, `uv python list` in the base image]**
- **Decision:** the agent image's tag carries a content hash, so the devcontainer cannot name
  it. `scripts/devcontainer-image.sh` (its `initializeCommand`) builds it through
  `agent.sh true` and tags it `riftweave-agent:devcontainer`. **[V 2026-11-08: the tagged
  image runs as `agent` with Python 3.13.12 and Claude Code 2.1.316 and validates the
  checkout at `/src`; the devcontainer CLI itself was not run, it is not installed here]**
- **Decision:** the pip cache volume becomes a uv cache volume (`riftweave-uv-cache`), since
  the image installs with uv; `clean-directories` lists the Python caches by path, because
  devops-tools takes paths, not globs.
- **Difference from the issue:** moving `fetch-docs` too would have been 22 counted files, so
  it is M5-22. There is no failing-vector step: this is tooling with no rule.
- **Why:** devops-tools now ships the runner, the shared base, and the agent image with its
  plugin start script; keeping a second copy here meant fixing both.
- **Open:** `./scripts/test.sh <args>` now appends the arguments to `unittest discover`
  instead of replacing it, so running one module is `./scripts/python.sh -m unittest <module>`
  **[A]**. The container mounts the checkout at its host path, not `/src`; only the
  devcontainer keeps `/src` **[V 2026-11-08]**.
