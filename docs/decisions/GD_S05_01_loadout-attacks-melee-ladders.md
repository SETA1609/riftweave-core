# GD_S05_01_loadout-attacks-melee-ladders Attacks by loadout, the jab, the full attack, and the melee perk ladders

Date: 2026-11-19

- **Decision:** an attack action is a new kernel function and command, `attack_sequence`, that runs one `combat` per strike, instead of new fields on `combat`. `combat` stays one roll and one result; a sequence's result is a list of strikes, which the `combat` result schema (one outcome, required fields) cannot hold. The loadout's row of `attack_sequences/core.json` gives the AP and the strikes; the table in the issue is the data, plus a row for empty hands (2 AP, like a light weapon) so every loadout an actor can hold has an attack. [A]
- **Loadout vocabulary:** `mainHand` (`empty`, `light`, `one_handed`, `two_handed`) and `offHand` (`empty`, `shield`, `buckler`, `light_weapon`, `weapon`, `two_handed`) in `schema.json`, written once for GD_S05_02's stances. A light main hand with a one-handed off-hand weapon uses the two one-handed weapons row; a loadout no row covers (an empty main hand with an off-hand weapon) is an error. [A]
- **Perks act only through targets:** `full_attack_strikes` (extra main-hand strikes at `full_attack.extra_main_attacks`, -20 then -30), `full_attack_off_strikes` (Twin Rhythm, at most one, at the off value -10), `mainhand_penalty` and `offhand_penalty` (Off-Hand Drill, a negative table value plus the add, never past 0; the jab's value too; the strikes perks add keep theirs), and `two_weapon_evasion_band` (Crossed Guard). `full_attack_off_strikes` and `two_weapon_evasion_band` are targets the issue did not name. The carry, Scissor Cut, and Circle Cut are `grant` flags; the Circle Cut flag is `can_circle_cut`, because an action key is already a number target (`circle_cut` is an action row). [A]
- **The carry:** a strike whose foe is down goes to the first foe in `foes` order still standing when a carry is left, and a full attack's later strikes follow it; Carry Through gives one carry per action, Reaping Arc one per drop. When the action's last strike drops a foe and a carry is left, one free strike with the same hand and value follows. This is how "the next strike of the same action (or one free strike, after an attack)" reads here; a full attack's last strike gets the free strike too. A circle cut carries nothing, since it already strikes every foe once. [A]
- **Scissor Cut:** "the off-hand weapon's damage dice once more" is the off-hand strike's damage roll doubled, so no extra roll is an input; it fires on the first off-hand strike that hits a foe an earlier main-hand strike of the same full attack hit, once per full attack. [A]
- **The full attack's AP:** it spends every AP the input's `ap` says is left and needs at least the attack AP + 1 (`full_attack.min_extra_ap`); an attack or a jab with `ap` below its cost is an error, and without `ap` it is not checked. The circle cut needs the same minimum. [A]
- **Order of a full attack's strikes:** the table's strikes, then the extra main-hand strikes, then the extra off-hand strike. [A]
- **Perk gates the issue left open:** Follow-Up AGI 5, Press On AGI 7, Off-Hand Drill AGI 6, Crossed Guard AGI 6 and Evasion 30, Twin Rhythm AGI 7, Scissor Cut AGI 8, Reaping Arc STR 7 and a melee skill 60, Circle Cut STR 8 and a melee skill 70; Carry Through keeps Cleave's STR 6 and a melee skill 50 and adds Piercing. [A]
- **Maneuver AP follows the loadout:** the `combat` input's optional `loadout` makes a maneuver's AP the loadout's attack AP plus its own (docs/core/actions.md#maneuvers). [A]
- **Renames:** `power_attack` is `full_weight`, `cleave` is `carry_through`, the `cleave_on_kill` target is `carry_through`. The reserved effect `cleave` (a splash enchantment no row uses) is renamed `spillover`, so `cleave` is no key at all. `heavy_power_attack_surcharge_ignored` (Brutal Charge's target) keeps its name: it names the act of a power attack, not the perk. [A]
- **Not here:** Full Weight's `melee_damage` multiplier is still not read by the pipeline (the target stays pending); the ranged full attack and the reload between strikes are `GD_S17_05_ranged-full-attack`'s; the stances that change the strikes are GD_S05_02's; the shield as an off-hand weapon is GD_S05_03's.
- **Each strike is a whole `combat` input** (review, 2026-11-19): a strike carries its hand's weapon (`weapon_properties`, `weapon_effects`; the off hand's own `off_weapon_*`, never the main hand's), and `situations` and `summoning` go to every strike, so a GD_S06_01 bound weapon, flanking, and GD_S06_04's Pincer Strike work in an attack sequence as in `combat`. A strike lists its landed weapon effects only when its hand has any, so a strike without a weapon effect reads as before. [V 2026-11-19]
- **Verified:** 35 `attack_sequence` and 5 new `combat` vectors pass in Python (`test_vectors`) and in Go (`go test ./...`, every vector through the core, the CLI, the server, WASM, and MCP); `validate.py`, the unit tests, the balance gate, gofmt, and go vet pass. [V 2026-11-19]
- **Not done:** `frontend/src/api/openapi.d.ts` is not regenerated (it needs a running server), as in GD_S06_01.
- **Differences from the issue:** a new command and vector file (`attack_sequence`, `backend/internal/attack/`, `backend/contract/attack_sequence.json`, `attack_sequence.json`), the Go loader and `combat` changes, the `cleave` effect rename, the empty-hands row, and the two extra targets are beyond the issue's file list; `examples/characters.json` held no ref to the renamed perks.
- **Risk: over the 20-file rule.** The split the rule names, a ruleset pull request and then a backend one, would leave the ruleset half's Go vector tests failing, since Go runs every vector file. The generated pages (`perk-ladders.md`, `data-model-diagram.md`, `contract-diagram.md`) and the playtest rerun add files of their own. Kept as one pull request.
