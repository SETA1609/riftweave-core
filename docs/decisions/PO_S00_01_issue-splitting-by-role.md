# PO_S00_01_issue-splitting-by-role Better documentation on how issues should be split, with a table reference

Date: 2026-11-18

- **Decision:** an issue belongs to one role and one story, and its id says both: `<ROLE>_<STORY>_<ISSUE>_<short-description>`, for example `BE_S07_03_character-list-cli`. The roles are in [ROLES.md](../issues/ROLES.md), the format and the old-to-new table in [docs/stories/README.md](../stories/README.md#ids). The issue number restarts in each story (owner, 2026-11-18: a global number would reach 999 soon). FE and BE each own the UX of their own surface, the frontend and the CLIs and TUI; there is no UX role (owner, 2026-11-18). This replaces the `B`/`F`/`T`/`D` prefixes proposed in M5-77, which is dropped.
- **Why:** a milestone id said nothing about the topic or who picks the work up, and M5 had become a catch-all. A role in the id lets a frontend dev, a game designer, or an agent filter its own work, and a story groups the issues one goal needs.
- **Migration:** done issues keep their ids (`M1` to `M6`, `APP`, `POST`, `SET`, `RW` are frozen). Every open issue was renamed and carries `Was: <old id>`; `Needs:` and `docs/issues/open/` links follow. Full-stack APP issues were split into a `BE` and an `FE` issue, the FE one needing the BE one. M5-61, APP-30, APP-43, and APP-48 have open pull requests and keep their ids; if one is still open after its merge, it takes the id reserved for it in the table. M5-76 is finished and waits for the close workflow, so it keeps its id. Prose mentions of old ids in docs, code comments, and decisions are not rewritten; the table resolves them.
- **Tooling:** `issue-id-pattern` in `tools/devops/pyproject.toml` accepts both forms, so `changelog-fragments`, `close-merged-issue`, and `roadmap-order` find the new ids in branch names, file names, headings, and `Needs:` lines [V 2026-11-18, devops-tools 5458d06].
- **Open:** devops-tools takes an issue's story from the text before its last `-` (`find_story_id_of_issue`), so for a new id the story column of `order.md` and the `Focus:` line do not group by `S00` to `S16` yet; waves, `ready`, `blocked by`, and the critical path work per issue. Fix in devops-tools (read the story from `_S<NN>_`) and bump the pin in its own PR [V 2026-11-18].
- **Risk:** this pull request is over the 20-file rule; almost every counted file is a new story or a new frontend issue, which the rule cannot split without leaving the tracker half renamed.
