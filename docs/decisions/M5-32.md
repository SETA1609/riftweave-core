# M5-32 Modifier targets are rows

Date: 2026-11-10

- **Decision:** a modifier's `target` is a key that names one row: an attribute, a skill, a
  derived stat, an action, a condition, a damage type, or a row of the new `modifier_targets`
  table. The op must fit the row's kind. Spec: `docs/core/modifier.md#target`; gate 4 in
  `docs/core/integrity.md`. **[V 2026-11-10, `validate.py` 47 of 47 files, 214 tests]**
- **Rows:** 84 core targets and 8 factions flags. Each is registered under the name the data
  already uses, so no modifier changed. **[V 2026-11-10]**
- **`pending` is judged by the golden vectors, not by reading code.** The issue's first draft
  checked the reference code. A text search of the code finds names such as `cast` and
  `crit_window` that mean something else there, so it would mark targets as read when no rule
  reads them. A vector is the repo's own test of a rule. 79 of the 84 core rows are pending; only
  `block_magic`, `bulwark`, `loot_roll`, `riposte`, and `shield_dr` have a vector. **[V 2026-11-10]**
- **Differences from the issue:**
  - Actions are a target table too. `docs/core/actions.md` already has a perk change a cost with
    `add` on the action's key (`sidestep` on `dodge`), so `aimed`, `cast`, and `dodge` resolve
    to their action rows. **[V 2026-11-10]**
  - The shared `modifier` definition in `schema.json` now gives `target` a key pattern. Every
    target in the data already matched it. **[V 2026-11-10]**
  - A module registers its own targets in its own `modifier_targets` file, listed in its
    manifest, as the factions module now does.
- **Open:** a module's `pending` rows are checked against its own `tests/`, the same as core.
  Whether a module should be held to that is not decided. [A]
- **Risk:**
  - `attack` resolves to the attack action, but `combat/situations.json` uses it for a bonus on
    the attack roll. The gate cannot see the difference. Filed in M5-37. **[V 2026-11-10]**
  - `block` is both a skill and an action, so the gate refuses a numeric modifier on it. No data
    uses one today. Filed in M5-37. **[V 2026-11-10]**
  - `darkvision_range` and `safe_fall_meters` hold metres. The rows say so, and M5-33 converts
    them. **[V 2026-11-10]**
  - A module that names a target without registering it now fails validation.
  - `go test ./...` was not run in this change: the Go 1.27 toolchain the module needs was not
    available. No Go file changed, and the backend reads none of the new files. [A]
