# M5-36 Composition bases are typed references

Date: 2026-11-11

- **Decision:** every `base` and `default_materials` entry is a typed reference, and a base file is a row whose key is its file name. Spec: `docs/core/keys.md`. **[V 2026-11-11, `test_typed_bases.py`]**
- **Decision:** every composed row is unchanged: all 127 monsters and items were byte-identical before and after. **[V 2026-11-11, compared the resolved rows]**
- **Why:** a base was a bare file name, or sometimes a reference in the same field, so the gate could not check it.
- **Difference from the issue:** the references are read in the two resolvers, not in `compose_row`, which still takes the loaded base. The gate walks the base files only for the shipped tree, so a test on a temporary tree sees its own rows. **[A]**
- **Open:** a module cannot yet add a base template: `module:` forms pass the schema, but the resolvers read only the core directories. **[U]**
